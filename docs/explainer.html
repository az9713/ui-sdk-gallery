UI SDK: building blocks that AI agents use to make and work apps

UI SDK is a free toolkit from Vercel and shadcn, released 12 November 2026. It lets an build the buttons, menus and lists of an app, and then use them.

No experience needed. Every dotted word is a technical term: click or tap it to see what it means.

3 · The bricks

You already use these behaviors every day

UI SDK has more than 50 behaviors. Here are 8 of them, with a place where you met each one.

createPopupA box appears next to a buttonSeen: the menu after you right-click on your desktop.
createSelectionPick one item, or manySeen: Shift-click to pick many files in File Explorer.
createTypeaheadType letters to jumpSeen: type "N" in a country list to jump to Norway.
createRovingFocusArrow keys move inside a groupSeen: arrows move between photos in a gallery.
createReorderDrag items into a new orderSeen: drag songs up and down a playlist.
createResizeDrag an edge to change sizeSeen: drag the edge of a window.
createViewportMove and zoom a big pictureSeen: pinch to zoom on a map app.
createVirtualizerShow only what fits on screenSeen: an inbox with 10,000 emails that still scrolls fast.

6 · The two halves

Agents as builders, and agents as users

      Stop the agent before it sends

  For developers
  
      
    Show the code and install commands
    
      An agent writes this, not you. It is the README's search field: the "Clear" button shows only when there is text, and after a click the cursor goes back to the box.
      
    
      import { createFocusRecovery, definePrimitive } from "@ui-sdk/core"

const searchField = definePrimitive({
  name: "search-field",
  state: () => ({ value: "" }),
  api: (context) => ({
    set: (value: string) => context.store.set({ value }),
    recovery: createFocusRecovery({ fallback: () => context.element("input") }),
  }),
  slots: (slot) => ({
    input: slot({
      attrs: (state) => ({ value: state.value }),
      on: { input: (event, { api }) => api.set((event.target as HTMLInputElement).value) },
    }),
    clear: slot({
      present: (state) => state.value !== "",
      attrs: () => ({ type: "button" }),
      press: ({ api }) => api.set(""),
      bind: (el, part) => part.api.recovery.bind(el, part),
    }),
  }),
})

const parts = createParts(searchField, { input: "input", clear: "button" })

  Map · the 3 axes
  
      Everything UI SDK gives you, on 3 orthogonal axes
      
  
      The Guide tab explains the idea. This tab is an inventory. UI SDK gives you 11 items. 3 orthogonal axes sort them, and each axis is 1 question about an item. Each item gets a position that no other item has.
      
  
       means independent: the answer to one question does not tell you the answer to another.
      
  
      
    
      
      AXIS 1
      
      Who is the agent?
      
      
        
        
      • Build: the agent makes the screen.
        • 
        
      • Use: the agent operates the screen. The website's word is "drive".
        • 
      
      
      
      From the sources. The website says "build and drive".
      
    
      
    
      
      AXIS 2
      
      What kind of help is it?
      
      
        
        
      • Mechanism: the code that does the work.
        • 
        
      • Knowledge: tells the agent what exists.
        • 
        
      • Check: shows that the result is correct.
        • 
        
      • Control: limits or records what the agent does.
        • 
      
      
      
      My own sorting. No source uses these 4 words.
      
    
      
    
      
      AXIS 3
      
      How large is the piece?
      
      
        
        
      • 5 layers, from the smallest brick to the finished look.
        • 
        
      • Behavior, , parts, complete part, style.
        • 
      
      
      
      The sources' terms, in my sequence.

  Map · axis 3
  
      Five layers, from brick to finished part
      
  
      The Build × Mechanism cell holds 5 items. Axis 3 separates them by size. Layers 2 to 4 are each made from the layer before it. Layer 5 is put on a complete part. The example is the teammate picker from the UI SDK website.
      
  
        
    
      1. 1
        Behavior no framework
        The agent takes 4 bricks: createPopup, createListbox, createSelection, createChange. Each brick does 1 job: open a box, move in a list, remember the choice, tell the app.
        2. 
    
      2. 2
        Primitive no framework
        definePrimitive joins the 4 bricks into 1 unit named user-picker. The unit has 3 named places for elements: trigger, content, option.
        3. 
    
      3. 3
        Parts 1 of 5 frameworks
        createParts from the React  changes the unit into 4 parts: UserPicker, UserPickerTrigger, UserPickerContent, UserPickerOption. The other 4 adapters give the same parts for Vue, Svelte, Solid and Web Components.
        4. 
    
      4. 4
        Complete part 1 of 5 frameworks
        A part that is ready to use. The starter library gives you these. The website shows 12, such as Calendar, Tree and Tabs.
        5. 
    
      5. 5
        Style optional
        The look: colors, fonts, spacing. UI SDK gives only optional starter stylesheets. You supply the remaining design.
        6. 
  
      
  
        
    
      • The framework is not a 4th axis. Layers 1 and 2 have no framework. The choice of framework starts at layer 3, thus it is a detail of axis 3.
        • 
    
      • Style is not a 4th axis. It has 1 item only. The reviewer says design is not the job of UI SDK.
        • 
  
      

      


      
  Map · try it · smallest set
  
      Why 3 axes, and not 2
      
  
      The rule for "smallest": use the fewest axes that give each item a different position. Remove an axis to see which items become the same.
      
  
      
    
      
      
      
      
      
    
      
    
      
  
      
  
      The count of 11 uses 2 groups: the bridge with WebMCP, and the 4 agent controls. The parts in a group have the same position, and a 4th axis would be necessary to separate them. This is one correct set, not the only one. Axis 3 separates items in 1 cell only. Thus "2 axes and 1 ordered list" is an equally accurate description.
      

      


      
  Map · checks
  
      Where the grid is correct, and its limits
      
  
      
    
      Correct
        
      
      • Each of the 11 items has a position that no other item has.
        • 
      
      • All 8 combinations of axis 1 and axis 2 are possible.
        • 
      
      • The 1 empty cell is a gap, not an impossible combination. A rule that limits which bricks an agent uses could fill it.
        • 
    
      
    
      Limits
        
      
      • The grid sorts items. It does not show what you can adopt alone. The Use column needs the Build column, because the bridge reads parts that describe themselves. The Build column does not need the Use column.
        • 
      
      • That dependency is my conclusion. The sources show the bridge only with UI SDK parts, and no source says it directly.
        • 
      
      • Axis 2 is my own sorting. A different person could select different words.

  Map · what it shows
  
      Four things you can read from the grid
      
  
      
    
      BUILD COLUMN
      The bricks are not a new idea
      The creator of React Aria says its hooks have been battle-tested since 2020. The creator of Zag.js says it has done this for years with state machines. The reviewer's result was correct work on the first try: 1 Tab stop against 15, a Lighthouse accessibility score of 100, and tests.
      
    
      USE COLUMN
      The reviewer calls this the more important half
      In his test the agent read about 13 KB against about 63 KB, which is about 5 times less. Time was 27 s against 28 s. Total tokens fell about 8%.
      
    
      CONTROL ROW
      Only the Use side has limits
      A person can approve, hide, redact and record what an agent does on the page. No item limits what an agent builds. Warning: without rules, the bridge accepts each action that has no label.
      
    
      OUTSIDE THE GRID
      Design gets 1 optional item
      A common reply on X: agents can already build working screens, and design is where they have difficulty. UI SDK does not correct that.
